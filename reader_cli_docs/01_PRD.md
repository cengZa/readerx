# 01. PRD：Reader CLI 产品需求文档

## 1. 背景

用户希望在终端中阅读小说或长文本内容，不依赖传统 App，也不希望每次手动下载、整理、打开文件。现有终端工具如 `cat`、`less`、`bat` 更偏向文件查看，不具备书架、章节、阅读进度、书签、搜索、笔记等阅读器能力。

因此，本项目希望构建一个面向终端用户的阅读器：

> 一个本地优先、可扩展数据源的 Terminal Reader。

## 2. 项目目标

### 2.1 短期目标

实现一个可真实使用的本地小说 CLI/TUI 阅读器：

- 支持导入 TXT 文件
- 自动识别章节
- 支持书架管理
- 支持终端分页阅读
- 支持阅读进度保存
- 支持关键词搜索
- 支持基础书签

### 2.2 中期目标

扩展为通用长文本阅读器：

- 支持 EPUB
- 支持 Markdown
- 支持笔记
- 支持 SQLite FTS5 全文搜索
- 支持 Source 插件抽象
- 支持 Lazy Loading 内容缓存机制

### 2.3 长期目标

演化为 Terminal Reading Workspace：

- 支持合法在线源
- 支持 RSS / Web Article
- 支持 AI 摘要、问答、人物关系、时间线
- 支持导出阅读笔记
- 支持同步和多设备迁移

## 3. 非目标

第一阶段明确不做：

- 不做番茄小说逆向接口
- 不做破解、批量下载、绕过登录或风控
- 不做内容分发
- 不做复杂云同步
- 不做完整 AI 阅读助手
- 不做 GUI 桌面端

## 4. 用户画像

### 4.1 核心用户

- 重度终端用户
- 开发者
- 喜欢用 CLI 管理个人工具的人
- 想在本地管理 TXT / EPUB / Markdown 的阅读用户

### 4.2 次级用户

- 希望把小说、文档、长文章统一收纳的人
- 希望对长文本做搜索、标记、笔记的人
- 希望未来接入 AI 做阅读分析的人

## 5. 核心使用场景

### 场景一：导入本地小说

用户有一个 TXT 文件，希望导入后按章节阅读。

```bash
reader import ./book.txt
reader list
reader read 1
```

### 场景二：继续上次阅读

用户上次读到某一章某一页，希望继续。

```bash
reader continue
```

### 场景三：搜索内容

用户想查找某个关键词出现在哪些章节。

```bash
reader search "剑气"
```

### 场景四：添加书签

用户读到重要段落，希望保存。

```bash
reader bookmark add
reader bookmark list
```

## 6. 产品定位

不要定位为：

> 某平台小说下载器。

应该定位为：

> 一个本地优先、可扩展数据源的终端阅读器。

核心价值不是“抓内容”，而是：

- 阅读体验
- 内容组织
- 本地搜索
- 进度管理
- Source 扩展能力
- 后续 AI 阅读增强
