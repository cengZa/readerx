# ReaderX 风险与边界

## 1. 合规与来源风险

ReaderX 的定位是阅读器，不是内容下载站或平台逆向工具。

允许的输入：

- 用户拥有或有权阅读的本地 TXT / EPUB
- 用户明确提供且有权访问的公开直链
- Project Gutenberg 等合法开放目录

禁止或不支持：

- 未经授权的平台私有接口
- z-library 等高版权风险来源
- 绕过登录、验证码、签名、风控、付费墙和访问控制
- 批量抓取、去广告、全文分发和内容托管

新增 Source 前需要同时确认授权边界、站点条款、请求频率和下载文件的许可证。

## 2. 数据安全与可恢复性

当前所有核心数据集中在一个 SQLite 文件中，优点是本地和简单，风险是：

- 用户误删数据库会同时失去书籍正文、进度、书签和笔记。
- schema 没有 migration，未来字段变化可能难以平滑升级。
- 没有内置 backup / restore / doctor。
- 首次导入的书籍记录与章节不是原子写入；章节事务失败时，可能残留没有章节的书籍记录。
- `--replace` 会清理该书的进度、书签和笔记，必须保持文档和提示清楚。

在数据管理功能完成前，版本升级应避免破坏性 schema 修改，并通过复制数据库文件进行人工备份。

## 3. 导入风险

### TXT

- 当前直接按 UTF-8 字节转字符串，没有编码检测或转码。
- 章节标题格式多样，可能漏分或误分。
- 无标题文本按固定 4000 rune 切分，不理解语义边界。

### EPUB

- 只解析常见 container/OPF/spine/XHTML。
- HTML 抽取采用轻量正则与 XML 处理，不是完整浏览器 DOM。
- 复杂 CSS、脚注、图片、表格、加密和损坏文件可能丢失信息或失败。

### 批量导入

- 当前顺序执行，遇到错误立即返回。
- 大文件没有进度反馈，容易被误认为卡住。

## 4. 在线访问风险

- URL 导入默认最大 100MB、超时 30 秒，但没有重试和速率限制配置。
- URL 后缀或 Content-Type 错误会导致误判或拒绝。
- 下载完成前会占用临时磁盘空间。
- HTTP 跳转由默认 client 处理，尚未限制最终域名。
- OPDS 服务变化、限流或不可用会直接影响 `source search`。
- 当前不保存远程 URL，无法审计或重放原始来源。

## 5. 搜索风险

搜索索引是 2/3-gram，不是 FTS5：

- 长文本会产生大量 `chapter_search_terms` 行，数据库体积可能增长明显。
- `LIKE` 精确校验仍需读取候选正文。
- 单字符搜索直接回退 `LIKE`，大书库下可能较慢。
- 没有 reindex 命令，索引异常只能重新导入或直接处理数据库。

## 6. TUI 与跨平台风险

- 中文、emoji、组合字符和不同终端的显示宽度并不完全一致。
- Windows 发布包已生成，但仍需要更多 Windows Terminal 实机回归。
- resize 目前按旧 `line_offset` 夹取新分页位置，没有用 `char_offset` 精确复位。
- 超大章节整章加载，可能造成启动延迟或内存峰值。
- TUI 直接通过窄接口调用存储，交互逻辑和持久化仍有耦合。

## 7. 预留设计风险

`sources` 表、`source_book_id`、`cover_url` 和 `content_status` 的多状态都是未来扩展预留。预留字段本身不是已实现能力，长期不使用会增加理解成本。

下一次引入 schema migration 时，应逐项决定：真正接入业务、补齐消费者，或者删除无效预留。
