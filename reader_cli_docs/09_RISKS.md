# 09. 风险与边界说明

## 1. 合规风险

本项目不应定位为任何特定平台的小说下载器。

尤其避免：

- 逆向 App 私有接口
- 绕过登录、签名、验证码、风控
- 批量下载版权内容
- 分发小说全文
- 内置未经授权的数据源

推荐定位：

> Reader CLI 是一个本地优先的终端阅读器。用户可以导入自己合法拥有或有权访问的文本内容。

## 2. 数据来源风险

### 官方 API

多数小说平台没有面向个人开发者的公开内容 API。

### 第三方 API

风险：

- 不稳定
- 质量不可控
- 随时关闭
- 版权状态不明

### 爬虫/逆向

风险：

- 违反服务条款
- 账号或 IP 被封
- 法律风险
- 维护成本高

## 3. 技术风险

### 3.1 TXT 格式混乱

问题：

- 编码不统一
- 章节格式不统一
- 广告/乱码/空行
- 没有章节

应对：

- 多规则章节识别
- 编码检测
- fallback 伪章节
- 导入预览

### 3.2 中文终端排版

问题：

- 中文宽度为 2
- 英文宽度为 1
- emoji 和特殊符号宽度复杂
- 终端 resize 后分页变化

应对：

- 使用 runewidth
- 同时保存 char_offset 和 line_offset
- resize 后重新分页

### 3.3 SQLite FTS 中文搜索

SQLite FTS5 默认中文分词能力有限。

第一阶段可先做 LIKE 或 trigram 简化方案；后续考虑：

- 自定义 tokenizer
- 外部索引
- Meilisearch / Bleve
- 简单 ngram 索引

### 3.4 EPUB 兼容性

EPUB 文件格式虽然标准化，但实际文件质量参差。

应对：

- 先支持常见 EPUB
- 记录解析失败原因
- 增加 testdata
- 不追求第一版覆盖所有格式

## 4. 产品风险

### 小说 CLI 用户群较小

小说阅读是消费场景，CLI 是开发者场景，重合用户有限。

应对：

- 不只做小说
- 扩展为长文本阅读器
- 支持 Markdown、技术文档、RSS、网页文章
- 加入 AI 阅读增强

### 过早做在线源会拖慢项目

在线源最大难点不是技术，而是稳定性与合规。

应对：

- 第一阶段只做本地
- Source 抽象预留
- 在线源作为可选插件，不作为核心路径

## 5. 推荐边界

应该做：

- Reader Engine
- Local Import
- TUI Reading
- Bookmark
- Search
- Notes
- AI Reading Assistant

不应该优先做：

- 平台逆向
- 批量下载
- 内容分发
- 去广告
- 破解类能力
